## Context

### 1. The rename is already analyzed — this change executes it

`redesign-cli-project-machine-grammar` design.md D7 analyzed `marketplace.json` → `agents.json` and
deferred it: "not implemented here, per explicit instruction … Recommended: separate change" — with a
condition that the follow-up "should explicitly decide: rename only, or also fold in the `agents.lock`/
`AGENTS.md`/`.agents/` naming family's rationale". This change is that follow-up and makes the decision
explicit (D2). That change also recorded in its spec ("The registry manifest filename and CLI verb are
independent concerns") that the CLI verb rename does **not** imply the manifest rename; both facts remain
true — ADR-019's verb rename is done, this change is the deliberate, separate manifest rename (D3).

### 2. Why now, concretely

`hiukky/ai` (the user's own marketplace: `agents.json` + `plugins/std|flow`) already uses the filename
this rename introduces, and `uze market add ~/ai` fails today:

```
Failed to add marketplace: bundle manifest is missing in /home/hiukky/ai/marketplace.json
```

The marketplace is correct; the check looks for the wrong filename. The pragmatic point of the rename is
that user marketplaces *already* name their registry manifest `agents.json` and UZE's own repo is the odd
one out.

### 3. `marketplace.json` names two unrelated things (from D7 Context §4)

- **UZE's own marketplace registry manifest** (ADR-012/015): the contract a marketplace root answers with
  — `{name, plugins: [{name, source, description, keywords}]}`. Renaming *this* is the change.
- **Vendor-owned, derived native-plugin catalogues** that share the filename because the vendor defines
  it: `.claude-plugin/marketplace.json` (Claude), `.agents/plugins/marketplace.json` (Codex). Read by
  `crates/uze-integrations/src/claude|codex/**`, generated by `republish_packages`. UZE does not control
  these filenames and this rename must never touch them.

After the rename, the filename itself carries the ownership signal: `agents.json` is UZE's registry
manifest; `marketplace.json` at vendor paths is vendor-dictated.

## Goals / Non-Goals

**Goals:**
- UZE's marketplace-root manifest is named `agents.json`, end to end (core parse errors, application
  load/validate, embedded `uze-official` snapshot, CLI-visible error messages, docs).
- The schema is untouched — same shape, same primitives; `~/ai/agents.json` parses as-is.
- No fallback/deprecation mode: one deterministic filename, errors name it.
- Vendor catalogues provably untouched (no `marketplace.json` UZE-owned reading remains).

**Non-Goals (explicitly not this change):**
- No change to the manifest **schema** (`owner` stays optional, no new fields, no `agents.lock`-style
  versioning in the manifest).
- No rename of the `~/.uze/state/marketplaces.json` registry file, `plugin_marketplaces.json` provenance,
  `Marketplace*` types, or the `market` CLI verb (unchanged per ADR-019/ADR-015; user-invisible).
- No compatibility alias reading `marketplace.json` (D4).
- No change to how UZE delivers plugins, the Store, integrations, or vendors' catalogues.
- No migration tooling — pre-1.0 alpha, one-file rename in a marketplace root, `git mv` + push for Git
  marketplaces.

## Decisions

### D1 — The naming family rationale wins: `agents.json` is what a marketplace repo already is

A marketplace repository — `AGENTS.md` / `agents.json` / `plugins/**` — *is* an agent registry: it
declares, for the whole repo, which agent skills/plugins exist ("agents" in the ecosystem sense of
`agents.lock`, `.agents/`, `AGENTS.md`). Marketplace roots in the wild (`hiukky/ai`)
already follow it. The rename aligns UZE's contract with that family and removes the two-unrelated-things
collision (§3) in one move. This is a file-identity decision, not a schema decision: `agents.json` keeps
the exact `MarketplaceManifest` shape.

### D2 — Rename only; do **not** fold in the rest of the naming family

D7's open question ("rename only, or also fold in the `agents.lock`/`AGENTS.md`/`.agents/` naming
family's rationale") is answered: **rename only**. Rationale:

- `agents.lock`, `AGENTS.md`, `.agents/` are *project-scoped* artifacts (what this project uses); the
  marketplace-root manifest is a *machine-scope / distribution* artifact (what a marketplace offers).
  They share a vocabulary, not a mechanism — and sharing a filename family already brings the useful
  signal without pretending they are the same kind of file.
- ADR-019 explicitly kept the domain name, state file, and CLI verb: "the `market` verb renames the
  existing `marketplace` verb (domain name, state filename, and internal types are unchanged — this is a
  CLI-vocabulary decision only)". Renaming `Marketplace*` types / `marketplaces.json` now would reverse
  that decision for zero user-visible benefit; the CLI verb `market` also namespaces the *commands*, not
  the file format.
- Scope control: every additional rename multiplies the diff (state file migration, provenance paths,
  types) for no behavioral change.

### D3 — CLI-verb rename and manifest rename stay independent facts

ADR-019 + the earlier spec's "independent concerns" requirement said the verb rename SHALL NOT imply the
manifest rename — and it didn't. This change *does* rename the manifest, as its own decision, after the
fact; the independence claim is reaffirmed and its spec requirement is updated accordingly (the verb
still doesn't imply anything; the filename change is deliberate, recorded in ADR-023).

### D4 — No fallback alias: `agents.json` or a loud error

A marketplace root that still holds only `marketplace.json` fails `market add` with
`bundle manifest is missing in <root>/agents.json` — no silent dual-filename mode. Rationale:

- Deterministic contract: one filename to grep, document, validate, and error on. A fallback would make
  "what does UZE read?" state-dependent on the root's age, and would keep both filenames in every
  marketplace forever.
- Pre-1.0 alpha precedent: this project has chosen clean breaks over permanent aliases before (ADR-019's
  alternatives, `remove` semantics reversal in ADR-019 §D). Migration is one `git mv` per marketplace
  root.
- The same strictness already applies to the embedded snapshot: it's renamed in-tree, so bootstrap never
  needs a compat path.

### D5 — Vendor catalogues are out of scope by construction

`.claude-plugin/marketplace.json` and `.agents/plugins/marketplace.json` stay exactly as they are:
filenames, paths, generation code, and tests (`tests/shared_agent_skill_root_naming.rs`,
`tests/plugin_first_vertical_slice.rs` read them deliberately). The rename touches zero bytes in
`crates/uze-integrations`. Any test that keeps reading `.agents/plugins/marketplace.json` is asserted
verbatim in tasks §2.2, not "fixed".
