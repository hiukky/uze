## 9b. A marketplace is a Git repository (decided 2026-09-06)

The rule, stated by the operator after three rounds of the lock still
reading as decoration for a `path:` marketplace: **a marketplace is always
a Git repository, local or remote**. Not because Git is how the bytes
travel — a directory does that — but because a commit is the only thing
that answers *are these the bytes I installed?* and *is there something
newer?* A directory answers neither.

- [x] 9b.1 `acquisition::marketplace::repository_of` states it: a source is refused unless it is a repository with a commit (`UzeError::MarketplaceNotARepository`, whose message carries the reason). A local checkout's `identity` is its `origin` — the URL a teammate clones — falling back to its own absolute path, which is still a valid Git URL and honest about resolving nowhere else. `fetch` and `identity` are separate fields because they differ for a local clone.
- [x] 9b.2 Installing always clones at a commit, local marketplace included (`materialize_marketplace_plugin_at`). Reading a working tree in place was what made a local marketplace unpinnable: the bytes are whatever their author last saved. A local clone is cheap — Git hardlinks it.
- [x] 9b.3 The layers separate: the machine registry (`~/.uze`) holds *where this machine reads it* (`/home/…/ai`), the project lock holds *what the project depends on* (`git: git@github.com:…` + `revision`). A path in a committed lock was never reproducible for anyone else. `register_marketplace` compares identities rather than `PackageSource` shapes, so a clone and its remote are recognized as one marketplace.
- [x] 9b.4 Reproduction prefers the local clone when this machine has one registered for the same identity, and the recorded URL otherwise. Same commit either way; a person who set up a local marketplace should not need the network to reinstall from it.
- [x] 9b.5 `LockedMarketplace.git` and `.revision` are non-optional: "a marketplace with no pin" is now unrepresentable. The entry is written from what the clone reported, so it cannot exist without the commit it was read at.
- [x] 9b.6 `reject_inline_credentials` asks per transport instead of refusing every `@`. Userinfo is a credential only over `http`/`https`; over SSH (`git@host:org/repo`, `ssh://git@host/…`) it is a user name and the secret is a key on disk. The old rule made every private marketplace unusable to protect against a secret that was not there — and became load-bearing the moment a local checkout's identity is its SSH `origin`. Closes 9.25.
- [x] 9b.7 `crosses_trust_boundary` asks *where the bytes are*, not how the source is spelled: a bare absolute path is local (Git hardlinks it), anything with a scheme is not — `file://` included, which Git routes through its transport layer and which is what "pretend this is a remote" is spelled as in tests. Without this, making local marketplaces Git-shaped would have started prompting for trust on every local install, changing a workflow by accident.
- [x] 9b.8 `parse_lock_str` refuses a duplicate key (`DuplicateKeyPolicy::Error`), the rule the manifest already held. A second `integrity:` silently replacing the pin is the case that matters.
