# Reproducible Agent Dependency Lock

Status: Accepted

## Context

Following ADR-016 (Project Agent Environment), UZE needs a file format for `agents.lock` that is:
- Small and human-readable
- Deterministic (repeated writes produce identical bytes)
- Vendor-neutral (no harness-specific state)
- Reproducible (contains enough info for fresh-machine install)
- Versionable in Git
- Independent of harnesses installed on the machine

The lock must persist reproducible identity for marketplaces and plugins. A marketplace alias like `ai` is UX; the identity is `source.url + resolved.revision`. On a fresh machine, `uze install` must reconstruct the environment using only the lock, without prior `uze marketplace add`.

## Decision

A project's agent environment is **two files**: `agents.yaml`, authored by a
person, and `agents.lock`, derived from it. Both are YAML (via
`noyalib::compat::serde_yaml`, replacing deprecated `serde_yaml`) with
schema version `version: 1`.

This ADR originally folded both roles into `agents.lock` and recorded the
split as a deferred non-goal. It is no longer deferred: the single file
carried intent (the isolation policy, a marketplace's declared source)
that could not be regenerated, which made it unsafe to delete and made
`resolved` a field nobody could rely on. The properties npm, bun, uv and
Cargo all hold — the lock is generated, exhaustive, verifiable,
reproducible offline, and safe to delete — are only reachable once the
manifest exists to derive it from.

**Manifest (`agents.yaml`) — authored, commented, edited in place:**
```yaml
worktrees:
  completion: pr
  link: [.env.local]

marketplaces:
  ai:
    git: https://github.com/hiukky/ai.git
    ref: main            # optional
    subdirectory: market # optional
  local-dev:
    path: ../local-marketplace

plugins:
  # pinned until the upstream fix lands
  flow: { marketplace: ai, ref: v0.3.1 }
  uze: { marketplace: uze-official }
```

**Lock (`agents.lock`) — generated, never edited:**
```yaml
# Generated by UZE. Edit agents.yaml instead.
version: 1

marketplaces:
  ai:
    source: { type: git, url: https://github.com/hiukky/ai.git }
    revision: 9f3a1c2d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0
    requested: { ref: main }
  local-dev:
    source: { type: path, path: ../local-marketplace }
    requested: {}

plugins:
  flow:
    source: { type: marketplace, marketplace: ai, plugin: flow }
    revision: 9f3a1c2d4e5f6a7b8c9d0e1f2a3b4c5d6e7f8a9b0
    version: 0.3.1
    integrity: sha256:1b4f0e9851971998e732078544c96b36c3d01cedf7caa332359d6f1d83567014
    requested: { marketplace: ai, ref: v0.3.1 }
  uze:
    source: { type: marketplace, marketplace: uze-official, plugin: uze }
    revision: embedded
    version: 0.0.0-alpha.8
    requested: { marketplace: uze-official }
```

**Key decisions:**
1. **Two files, one direction** — `agents.yaml` → resolution → `agents.lock`. Never the reverse.
2. **`agents.yaml` is the workspace anchor** for a consumer, replacing `agents.lock` in `workspace.rs`. A project that declared but never resolved is still a workspace.
3. **The isolation policy moves to the manifest** — every field of it is a decision, not a resolution.
4. **`version: 1`** (not `lockfileVersion`) — short, explicit.
5. **`marketplaces` top-level in both** — reproducible identity, not just alias.
6. **`source.type: git | path | embedded`** — mirrors `PackageSource` variants.
7. **`revision`** — Git commit SHA, `embedded` literal, or absent for `path` (non-reproducible). Flattened out of the old `resolved` nesting: in a file that holds nothing but resolution, a `resolved:` key names the obvious.
8. **`integrity: sha256:...`** — a real content hash over ingested bytes, verified on install. No longer reserved: a lock that pins nothing is a description, not a lock.
9. **`requested`** — the manifest declaration each entry was resolved from, so staleness is decidable offline by comparing the two files (`uv.lock`'s `[package.metadata] requires-dist` serves the same purpose).
10. **YAML on both, JSON left alone elsewhere** — `plugin.json`, `marketplace.json`, `hooks.json` and `mcp.json` keep their format. Two of them are adjacent to an external standard, and none has a real authoring population yet; a second parser path in four places would be carried forever to remove friction nobody is feeling. Revisit per-file when an author asks.
11. **`BTreeMap` ordering** — deterministic serialization.
12. **`write_atomic`** — nonce temp + rename + sync (same as other UZE state).
13. **`path` type** — explicitly non-reproducible: no revision, no integrity.
14. **`embedded` type** — `revision: embedded` literal (bytes in binary).
15. **The primary checkout owns the isolation policy; worktrees inherit it and never override it.** The policy is one declaration per repository, living in the manifest of the checkout the worktrees are born from. There is no scope below it (a worktree's own manifest is ignored) and none above it (no machine-level setting resolves an undeclared policy) — `WorktreePolicy::instructions()` is projected into the tracked `AGENTS.md`, so anything resolved outside the project would make the same repository produce different agent instructions per machine, and every `context reconcile` rewrite a shared file. ADR-019's machine/project boundary holds unchanged.
16. **Nothing is created on arrival.** An undeclared policy already resolves to `Handoff`, so a project with no manifest works; the manifest appears on `uze install` or on the first declaration, never because a directory was opened. No new command was added for it: `install` is already the explicit act of setting a project up, and the rule being enforced is "not on arrival", not "only from a dedicated verb". Discoverability comes from the workspace client naming the policy in effect and its provenance, which teaches more than a file that appeared by itself.
17. **No lock until something resolves.** A policy-only project has no lock, and removing the last entry deletes it. This replaces the original "empty lock is valid" requirement.
18. **No migration code** — the pre-split `agents.lock` is rejected as malformed, naming the two files that replace it. Pre-1.0; stale state is cleaned, not accommodated.

**Reproducibility semantics:**
- `install` uses `resolved.revision` (frozen), never re-resolves `source.reference`
- Lock revision X wins over global marketplace pointing to Y
- Offline + Store hit → success; offline + Store miss → `Unavailable`
- `desired ≠ actual` is valid state (diagnosticable via `plan`/`status`)

**Trust boundary:**
- `agents.lock` NEVER grants trust
- `authorize` is always called if `crosses_trust_boundary` + `executable_capabilities`
- Fresh machine with locked MCP server → `TrustRequired` error, not silent execution

**Lifecycle:**
- Lock absent → create `version:1` + entries
- Lock exists → merge `BTreeMap` (preserve order, other entries intact)
- Same resolution → no-op (idempotent via `BTreeMap` + `to_string`)
- Malformed YAML → `Err(MalformedLock)`, no overwrite
- Unknown version → `Err(UnsupportedLockVersion)`
- Marketplace source conflict → `Err(MarketplaceSourceConflict)`, not silent

**Atomicity order:**
```
resolve → authorize → acquire → validate → ingest → republish → attach → persist lock
```
Lock is persisted after `ingest` succeeds (avoids orphan lock pointing to non-ingested package). If `attach` fails, lock persists but `doctor/plan` reports `delivery missing/drifted`.

## Consequences

**Positive:**
- Fresh-machine repro: `git clone + uze install` works without prior setup
- The lock is safely deletable: intent survives in `agents.yaml`
- Integrity is verified on install, so a moved tag or a rewritten history is caught rather than silently delivered
- Staleness is decidable offline, with no network and no re-resolution
- A repository projects the same `AGENTS.md` on every machine, whatever each developer prefers locally
- Trying UZE in a repository writes nothing into it until something is declared
- Deterministic: repeated `uze flow@ai` produces identical bytes
- Non-reproducible sources explicit: `path` type with empty `resolved`
- Trust boundary preserved: lock never bypasses consent
- Atomic: lock persisted only after successful ingest

**Negative:**
- New dependency: `noyalib` (maintained fork of deprecated `serde_yaml`) — now load-bearing for two files rather than one, which is what makes the parser choice worth revisiting (see design.md)
- Two files where there was one: every command that wrote the lock now edits the manifest and regenerates the lock
- A project's format changes with no migration path; existing locks must be rewritten by hand once
- A person who prefers one completion behavior across their projects declares it per project; there is deliberately no machine-wide setting to inherit from
- New error variants: `UnsupportedLockVersion`, `MalformedLock`, `MarketplaceSourceConflict`, `MarketplaceMismatch`
- `path` type is non-reproducible (explicit warning, not silent)

**Neutral:**
- `integrity` field reserved but not implemented (commit is identity)
- `uze sync` deferred (use `install` for now)
