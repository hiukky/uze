# Why uze

Coding agents each have their own plugin format, their own skills directory,
their own way of reading project instructions. Maintaining the same skill or the
same project context four times over is how agent setups rot.

And once you run more than one at a time, they collide: two agents editing one
checkout, with your own uncommitted work in the middle.

uze answers both with one idea: **agents come and go; your work stays.** What a
project declares — its plugins, its instructions — is written once and delivered
to whichever agent you run. Where an agent works is a checkout of its own, and
what it did is read from Git, not from what it says.
