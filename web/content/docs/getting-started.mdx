# Getting started

## Install

<Callout type="warn">
  uze is alpha — no packaged release has shipped yet. Building from source is the only way to
  run uze today; the installer below already exists and will just say so until the first
  release does.
</Callout>

<Tabs items={['Linux', 'macOS', 'Windows', 'Source']} defaultIndex={3}>
  <Tab value="Linux">
    ```bash
    curl -fsSL https://uze.hiukky.com/i | sh
    ```

    Prebuilt binary for `x86_64`/`aarch64`, glibc or musl auto-detected; verifies a SHA-256
    checksum before installing into `~/.local/bin` (or `$XDG_BIN_HOME`). Not live yet — it prints
    build-from-source instructions until the first GitHub release ships.
  </Tab>
  <Tab value="macOS">
    Planned, not yet supported — see the **Source** tab.
  </Tab>
  <Tab value="Windows">
    Planned, not yet supported — see the **Source** tab.
  </Tab>
  <Tab value="Source">
    ```bash
    git clone https://github.com/hiukky/uze.git
    cd uze
    cargo install --path . --locked
    ```

    Works today on anything Rust's stable toolchain targets.
  </Tab>
</Tabs>

## Set up harnesses

`uze setup` detects the four supported harnesses on your machine and provisions any missing
binaries through each vendor's official installer:

```bash
$ uze setup
▸ Provisioning 4 harnesses through official routes…
[1/4] Claude Code: ready (verified)
[2/4] Codex: ready (verified)
[3/4] OpenCode: ready (verified)
[4/4] Antigravity: ready (verified)
```

Setup is idempotent — running it again refreshes recorded facts instead of duplicating state.
Use `uze setup <name>` to target one harness (`claude`, `codex`, `opencode`, `agy` — or their
stable ids `claude-code`, `antigravity`).

<Callout type="warn">
  The installer output is buffered per harness under `$UZE_HOME/state/logs/setup-<id>.log`;
  use `--verbose` to stream it.
</Callout>

## Add a plugin

Project shorthand adds a plugin from a marketplace to the current project:

```bash
$ uze flow@ai
Claude Code: native (plugin:flow)
Codex: native (plugin:flow)
OpenCode: native (skills/flow)
Antigravity: native (plugin:flow)
```

Machine-scoped verbs (`add`, `remove`, `update`, `market`, `plugin`, `harness`) manage the
machine-wide Store; project-scoped verbs (`context`, plus `install`/`remove` against
`agents.lock`) manage the current project. Neither touches the other's state.

## Check the health

```bash
$ uze doctor     # store, harness detection, attachment health, ledger
$ uze status     # how this project's context reaches each harness
```

## Terminal UI

Run `uze` with no arguments for the terminal UI: overview, marketplace, plugins with per-harness
delivery, harness drawer with compatibility per capability, and doctor.

## A fresh project

On a new clone, `agents.lock` records the project's plugin set:

```bash
$ uze install     # install this project's environment from agents.lock
```
